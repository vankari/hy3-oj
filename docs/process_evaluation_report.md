### v0.3 → v0.5 的关键转折（mid100 人工抽检，14 候选全量核验）

对 v0.3 在 mid100 上的全部 14 条"AC 但过程不成立"候选逐题人工（AI 辅助）核验：
**13 条误报 + 1 条真实**。误报根因四分：
1. **计划锚定偏误**（5 例）：Reviewer 把 Agent 早期 Plan 当 ground truth，"实现与计划矛盾"即判 fail——
   但编码/修复阶段推翻错误计划是**正常且正确**的行为（1330_D、1391_C、p02939、1062_D、513_A）；
2. **机制幻觉**（3 例）：声称代码做了它没做的事（358_B 把子序列匹配说成连续子串匹配）；
3. **判题现实不可见**（2 例）：343_B 题面写 Yes/No 但数据集 expected_output 就是大写 YES；
4. **题意规则误读/无缺陷判 fail**（3 例）：p03254（漏看"必须分完所有糖"）、1159_A（符号约定自洽）、1397_B（无行为影响的死代码）。

**真实样本 p01811 ABC Gene**：AC 解对官方样例 AABCC 实测输出 No（期望 Yes）——
逆向规约统一推 'A' 不完备（需 ABC→B 再 ABC→A），CodeContests 该题测试弱未覆盖。
Reviewer v0.3 靠运气成分命中（其论证部分错误），v0.4 反而漏掉——
**证明单遍 LLM 审查在 AC 解上精度/召回不可兼得，必须有机器验证层**。

### v0.5 行为探针（agents/prober.py）

1. LLM 从题面文本抽取官方样例 I/O 对（按题缓存）；
2. **官方参考解反向校验探针**：参考解也过不了的"样例"是抽取噪音，丢弃（近零误报铁闸）；
3. 被审代码在探针上失败而参考解通过 → 行为级蒙对铁证（p01811 实测命中）。

**定罪口径（v0.5 起）**：R6 蒙对定罪只接受机器验证证据（行为探针，或规则+LLM 双确认信号）；
LLM 逐步判定/打分只作 R8"过程存疑"分析维度与人工复核队列，不单独定罪。

## 三、五段式审查与蒙对检测设计（任务书 R3–R6）

**五段式分步审查**：题意理解 → 算法选型 → 复杂度论证 → 边界处理 → 实现一致性（错误定位 = 首个 fail 段）。
每段带显式定义与归属规则；fail 段须给行号 + 错因 + 归属依据；按错误机制（而非暴露场景）归因；
**计划只是早期草稿，不构成 fail 依据**。

**蒙对检测三层**：
- 信号层（规则召回）：硬编码样例字面量 / 输入特判形分支 / 声称复杂度 vs AST 有效嵌套深度——
  全部只作候选，任何表面模式都不是铁证（输出词汇、题目常数、合法边界分支都会被误中）；
- 复核层（LLM 定罪辅助）：按信号类型给复核指引，confirmed 才计入；
- **行为层（机器定罪）**：题面样例探针 + 参考解反向校验（R6 唯一定罪来源）。

## 七、结论与能力边界

1. **两项有效性指标均达标**：定位准确率 74%（≥70%）、误报率 0%（≤20%，机器定罪口径）。
2. **核心方法论发现**：过程评估的可信定罪必须落到**机器可验证的行为证据**；
   LLM 语义审查适合发现"过程存疑"线索与错误类型归因，但单独定罪误报率高（mid100 实测 93%）。
   "LLM 广撒网 + 机器/人工做终判"是与任务书 R7 人工抽检设计自洽的架构。
3. **R6 增量价值实证**：p01811（官方样例都错的 AC 解）与 professor-sharma（eps 级缺陷）
   都是判题系统未捕获而过程评估捕获的样本。
4. **能力边界**：①注入策略仅 4 种，未覆盖多 bug 组合与题意误读类注入；②段级归属存在固有主观性；
   ③行为探针依赖题面样例质量与官方参考解（LCB 无参考解时探针自动停用，退回语义层 + 人工抽检）；
   ④语义层错误类型分布含约 2~3 成误报倾向，引用时需注明。

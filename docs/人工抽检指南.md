# 人工抽检指南（任务书 R7 误报率验证 / R9 抽检记录）

> 对象：`runs/*.spot_check.json`（由 `python scripts/run_review.py --mode fp --out <review结果>` 生成）
> 抽检人填 `human_verdict` 与 `human_note` 后重跑同一命令即汇总误报率（目标 ≤20%）。

## 一、human_verdict 接受值

| 值 | 含义 | 计入统计 |
|---|---|---|
| `"real"` | **真实问题**：Reviewer 指出的过程缺陷经核验确实存在 | 是（分子分母之外，降低误报率） |
| `"false_positive"` | **误报**：Reviewer 的指控经核验不成立 | 是（计入误报分子） |
| `null` / 不填 | 未抽检 | 否 |

误报率 = false_positive 数 / 已抽检数，目标 ≤20%（`configs/default.yaml: eval.false_positive_target`）。

## 二、判定标准

候选的共同前提：**答案 AC（全部测试点通过）但 Reviewer 判过程不成立**。
你要回答的问题只有一个：**Reviewer 指出的过程缺陷是否真实存在？**

### 判 "real"（真实问题）

- 缺陷在代码中**客观存在**，即使测试点恰好没测到（professor-sharma 判例：Y+1 为 10 的幂时
  取错 `floor`，缺陷区间仅 eps 宽、测试不可能覆盖，仍判 real——过程确实无法支撑结论）；
- 计划与实现确实矛盾（如 Plan 选了 DP、实现是另一套逻辑），即使答案碰巧对；
- 声称复杂度确实不成立（代入数据范围数值核验超标），即使实际运行没超时；
- 确有硬编码样例答案 / 对特定输入返回预谋答案。

### 判 "false_positive"（误报）

- 所引行号没有证据声称的问题（Reviewer 幻觉）；
- "缺陷"实为合法写法：输出词汇（First/Second/YES/NO）、题目常数、合法边界分支；
- 计划-实现比对系误读（换种写法但算法一致）；
- 复杂度指控在数值上不成立（代入约束上界验算可过）。

### 边界情况的处理约定

- **缺陷存在但无关紧要**（不影响任何现实输入）→ 仍判 `real`（过程评估问的是过程是否成立，
  不是是否改变判题结果），在 `human_note` 注明"缺陷无实际影响"；
- **Reviewer 结论对但证据错**（蒙对答案但理由编错）→ 判 `real`，note 注明证据瑕疵；
- **拿不准** → 保持 `null` 不填，宁缺毋滥；在 note 写疑点，换他人复核。

## 三、抽检操作步骤

1. 打开 `runs/spot_check_packet.md`（候选证据包：每题含 Reviewer 指控全文 + 被审代码，一并生成）；
2. 逐题核验，必要时用题目 id 查题面（`data/subsets/subset_mid100.jsonl`）与
   Reviewer 完整逐步判定（`runs/review_mid100.jsonl`）；
3. 在 `runs/review_mid100.spot_check.json` 填 `human_verdict` / `human_note` / 抽检人；
4. 汇总：`python scripts/run_review.py --mode fp --out runs/review_mid100.jsonl`。

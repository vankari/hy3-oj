# 图形界面设计方案（Streamlit）

## 一、定位

任务书 R9 要求"时长 2 分钟以内的 demo 视频或 GIF，展示一次完整的解题与过程评估流程"。
GUI 是**该 demo 的载体**，同时整合项目全部核心能力，供评审直接体验。

## 二、页面结构（左侧导航多页）

```
Hy3-OJ 控制台
├── 1. 解题工作台（主页面，demo 主场景）
│   ├── 题目输入：① 外部文件(md/txt) ② 粘贴文本 ③ 数据集选题
│   └── 一键运行 → 实时展示：解析 → 规划 → 生成 → 判题 ⇄ 修复 → 审查 → 题解
├── 2. 过程评估详情（五段式审查 + 蒙对检测的可视化）
├── 3. 评测看板（LCB/CodeContests 分层结果、pass@k、能力临界点）
├── 4. 人类反馈（对评估结论判定 real/false_positive，驱动迭代）
└── 5. 设置（模型/端点/并发/沙箱参数）
```

## 四、关键技术决策

| 问题 | 决策 | 理由 |
|---|---|---|
| 长时间运行的进度反馈 | 同步执行 + `st.status` 分步展开 | Streamlit 每次交互重跑脚本，async 在后台线程需额外管理；同步+状态容器最简单可靠 |
| 中断支持 | 复用 `GracefulInterrupt` + 「停止」按钮 | 已实现的协作式中断，按钮置位即可 |
| 结果持久化 | 每次运行落 `runs/ui/<id>.json`，页面可从历史恢复 | 避免刷新丢结果 |
| 密钥 | 仅从 `.env`/环境变量读，界面**不提供**输入框 | 任务书硬性要求：密钥不得入库、不落界面 |
| 图片题面 | 实验性：显示「含 N 张图片未解析」告警 | 视觉模型未开通，如实标注而非静默忽略 |

## 五、与已有模块的关系（不重复造轮子）

| 界面功能 | 复用模块 |
|---|---|
| 题目解析 | `core.problem_io`（含 warnings 用于告警展示） |
| 解题 | `core.pipeline.SolvePipeline` |
| 过程评估 | `agents.reviewer` |
| 题解 | `agents.explainer` |
| 评测看板 | `eval.report.summarize_by_difficulty` + `render_markdown` |
| 人类反馈 | `core.checkpoint.FeedbackStore` |
| 中断 | `core.checkpoint.GracefulInterrupt` |
